# Compliance requirements and evidence matrix

Status: proposed requirements and controls requiring applicability review and evidence; this matrix does not certify compliance. Implementation status is recorded in the [implementation plan](../planning/implementation-plan.md#status) and [quality gates](../quality/README.md). The **laboratory** is the covered entity running its own installation on one computer ([ADR 0009](../architecture/decisions/0009-single-computer-local-lis.md)); a **service provider** is an entity that would host optional external services, with business-associate obligations where they handle laboratory PHI ([ADR 0010](../architecture/decisions/0010-optional-cloud-services.md), proposed). State- and laboratory-specific applicability remains open. Read the [regulatory landscape](../research/regulatory-landscape.md) for applicability and the [source register](../research/sources-regulatory.md) for source dates and research limitations.

An agent can maintain this matrix and collect evidence. The named human **role** must decide applicability and acceptance; no person has yet been assigned to these roles. “Verification evidence” is a future acceptance requirement, not evidence that already exists. Acceptance scenarios run on synthetic data in development and do not replace laboratory validation. Source obligations and proposed engineering mechanisms are different: a rule can require accurate records without requiring the particular storage design proposed here.

Classes: **B** = binding when applicable; **A** = accreditation/contract overlay; **C** = payer coverage or payment condition, applying only when billing that payer for that date of service; **G** = government guidance or voluntary framework; **P** = proposal/watch item; **D** = project design requirement or operational gate. All entries are **open**. Production acceptance requires an applicability determination, named accountable person, implementation reference, evidence link, residual-risk disposition, and dated approval for each applicable entry.

## Acceptance record format

For each applicable REG ID, future deployment evidence must identify:

1. Laboratory/entity, site, program, jurisdictions, deployment and release/version.
2. Applicability decision, controlling source edition/date, and named accountable human.
3. Requirement interpretation, implementation/SOP references and test or inspection evidence.
4. Evidence result, unresolved deviations, compensating controls, and residual-risk decision.
5. Approval date, re-evaluation trigger and next review date.

Do not mark a requirement complete merely because documentation exists, a checklist is checked, an agent approved a PR, or a vendor advertises compliance. Organizational obligations require organizational evidence; laboratory validation requires laboratory ownership.
