# Risk register

Active risks remain open unless a row says otherwise; controls and implemented evidence are distinguished below. Severity describes plausible consequence, not a measured probability. Critical = potential patient/result-integrity or major confidentiality harm; high = material operational/compliance/lifecycle failure. Named owners and residual-risk decisions are required before the affected pilot gate.

Fraud-and-abuse and payer risks describe exposure the product could create or fail to make visible; they are not legal conclusions about any laboratory.

The register covers the local desktop LIS and separately scoped proposals for optional external services ([ADR 0009](../architecture/decisions/0009-single-computer-local-lis.md), [ADR 0010](../architecture/decisions/0010-optional-cloud-services.md), [ADR 0012](../architecture/decisions/0012-rust-tauri-desktop-application.md)). In this register, "laboratory" is the legal lab entity running its own installation, and "service provider" is a proposed provider of optional hosted services.

Consequence: unsigned, SmartScreen-blocked or Gatekeeper-blocked installers; updates that cannot be verified; labs tempted to bypass signature checks | High | Decide the signing route and publisher name early for each OS (Q-19, Q-34); Minisign and package-signing keys held offline or in an HSM with a documented rotation plan; OV certificate with an HSM key as fallback; certificate expiry tracked (460-day maximum from 2026-03-01); installers and update manifests verified before install, with no bypass ([technology research §4](../research/single-pc-technology.md#4-packaging-signing-and-updates), [desktop stack research](../research/desktop-application-stack.md#per-platform-matters)); VAL-37 | Technical maintainers + project owner |
| RISK-54 | Security fixes in Tauri, Rust crates, the bundled SQLite or the UI's npm dependencies are not shipped promptly through the lab-approved channel, or a pinned dependency (for example Typst, whose API changes between minor versions) forces an unplanned migration. Consequence: labs run vulnerable components or face an unplanned migration with full revalidation | High | Pinned toolchain and dependencies with an SBOM; dependency security releases through an expedited, still lab-approved channel; Typst wrapped behind one renderer module; support window per version stated (Q-34); health check shows the installed release's support status ([ADR 0012](../architecture/decisions/0012-rust-tauri-desktop-application.md), NFR-13); web-engine updates outside our releases are RISK-57; VAL-37/48 | Technical maintainers |
| RISK-55 | Telemetry, crash reports, logs or support bundles from the application carry PHI off the host. Consequence: the receiving project or service provider becomes a business associate of every installation without a BAA; PHI held outside inventory and retention controls | High | PHI-free telemetry by default; no crash dumps or raw logs leave the host; opt-in support sessions only under a BAA, logged and time-limited; inspection of outbound data per release (REQ-SVC-003, NFR-32, REG-044, [§15.1](../research/regulatory-landscape.md#151-hipaa-role-of-each-hosted-service)); VAL-47 | Privacy officer + security officer |
| RISK-56 | Results are missed while the application is closed, the OS session is signed out or the computer reboots (including an unattended OS update): there is no background service, so nothing listens. An analyzer that gives up retransmitting, overwrites its buffer or treats a timeout as delivered, or a watched-folder file replaced before import, loses results. Consequence: delayed or missing results, specimens re-run or results entered by hand with transcription risk | High | App kept open and the OS session signed in, with keep-awake while listeners are active, a close warning, optional start at OS sign-in, and power and update settings in the lab's setup checklist; acknowledgement only after durable receipt, so senders retransmit; startup reconciliation of interrupted imports and expected results, with the closed interval recorded and a work item per missing result; listener status on the sign-in screen and in the health view; each analyzer's retransmission and buffer behavior recorded during interface setup (REQ-OPS-013, REQ-INT-009, REQ-OPS-008, WF-10, Q-04, Q-18, [ADR 0009](../architecture/decisions/0009-single-computer-local-lis.md#consequences)); VAL-56, VAL-50 | Laboratory operations + interface owner |
| RISK-57 | Web-engine differences, or engine updates outside our releases (WebView2 Evergreen, macOS WKWebView, distribution WebKitGTK), break or degrade the UI on one OS, notably Linux WebKitGTK with its known rendering and GPU-driver problems. Consequence: a screen renders wrongly or not at all, a worklist becomes unusable at volume, or a displayed value is misread, on one platform only | High | Clinical logic, gates and calculations only in the Rust engine; conservative forms-and-tables UI without canvas-heavy rendering; every release passes the same critical journeys and a 10,000-row worklist check on each supported OS and engine; a UI smoke check after OS or web-engine updates before clinical use; the webview version is recorded in each session's audit context; a failed platform gate blocks support for that configuration pending remediation or a stack decision review; no WebView2 Fixed Version bundle is selected (NFR-33, NFR-13, Q-29, [ADR 0012](../architecture/decisions/0012-rust-tauri-desktop-application.md), [desktop stack research](../research/desktop-application-stack.md#the-cost-of-tauri-three-web-engines-and-linux), [ENG-130–ENG-136](../research/sources-engineering.md#desktop-application-stack-sources-2026-10-12)); VAL-57 | Technical maintainers + laboratory technical lead |

For new risks record initiating event, affected workflow/data, consequence, existing versus proposed controls, detection, scenario evidence and residual-risk acceptance. After testing, record failures and actual mitigation results rather than lowering severity because a design document exists. [Validation scenarios](../quality/validation-plan.md) provide the starting evidence map. Strategic risks (RISK-15, RISK-52), the partner-integrity part of RISK-33 and the legal part of RISK-47 are closed by discovery evidence and project-owner or counsel decisions, not by software tests.
